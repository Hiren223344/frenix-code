# Research & Analysis Excellence Skill (Ultra-Pro)

## 1. THE DEEP DIVE PROTOCOL
*   **Documentation Mining**: Before suggesting a library, read its "vnext" docs, GitHub issues, and Discord/X discussions. Understand the "Hidden Gotchas" before implementation.
*   **Source Code Auditing**: Use `webfetch` to read the actual source of open-source packages. Don't trust the README; trust the implementation.
*   **Comparative Analysis**: When choosing a tool (e.g., PandaCSS vs Tailwind), create a "Trade-off Matrix" comparing performance, DX, and longevity.

## 2. PROBLEM INVESTIGATION
*   **GitHub Issue Hunting**: If a tool is failing, search its issue tracker for similar stack traces. Track the "Resolution Status" (Open, Fixed, Workaround) and present it clearly.
*   **Tech-Spec Synthesis**: Convert vague project requirements into a specific "Technical Specification" document before any code is written.

## 3. COMPETITIVE INTELLIGENCE
*   **Benchmarking**: Analyze competitors' performance (Core Web Vitals), SEO strategy, and feature sets (via `web-screenshot`).
*   **Pattern Recognition**: Identify "Best of Breed" UI/UX patterns in high-end products (Linear, Vercel, Stripe) and adapt them to the current project.

## 4. EVIDENCE-BASED DECISIONS
*   **Proof of Concept (PoC)**: For high-risk decisions, architect a minimal, isolated PoC to verify the hypothesis.
*   **Data Backing**: Every architectural choice must be backed by a link to documentation or a performance benchmark.

## 5. FORBIDDEN (RESEARCH SLOP)
*   **NO Lazy Googling**: Don't just read the first search result. Look for peer-reviewed blogs, official docs, and source code.
*   **NO Assumptions**: Never assume a library handles X. Verify it via code or docs.
*   **NO Outdated Info**: Always check the "Last Updated" date of the documentation or issue. BANNED: Following a 2-year old medium article for a fast-moving framework.
*   **NO Uncited Claims**: If you say X is faster than Y, you MUST provide a benchmark or a logical proof.

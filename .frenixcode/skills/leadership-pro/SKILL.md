# Technical Leadership & PR Excellence Skill (Ultra-Pro)

## 1. ELITE PR REVIEWS
*   **Logical Soundness**: Review for more than just syntax. Check for edge cases, race conditions, and architectural alignment with `master-ultra-pro`.
*   **Readability First**: Code is read more than it is written. Refuse any PR that uses "Clever" logic at the cost of "Clear" logic.
*   **Constructive Feedback**: Every "Request for Change" must explain *Why* and provide a *Better Alternative*.

## 2. TECHNICAL DEBT MANAGEMENT
*   **The "Scout" Rule**: Always leave the codebase cleaner than you found it. If you touch a file for a feature, fix a small lint or doc issue simultaneously.
*   **Deprecation Strategy**: When introducing a new pattern, provide a clear roadmap for removing the old pattern. Use `@deprecated` JSDoc aggressively.
*   **Refactoring Budget**: Proactively suggest refactoring when a module's "Complexity Score" exceeds team standards.

## 3. ENGINEERING CULTURE
*   **Mentorship**: When the user asks a question, don't just give the answer—give the *Context* and the *Mental Model* behind it.
*   **Documentation Stewardship**: Mandate that every new feature includes an update to `memory.md` or a new `README.md` entry.
*   **Standards Enforcement**: Act as the "Guardian of the Stack". Prevent library bloat and "Pattern Drift".

## 4. INCIDENT LEADERSHIP
*   **Blameless Post-Mortems**: After a production error, lead the investigation using the "5 Whys" from `debugging-pro`. Focus on fixing the *Process*, not the *Person*.
*   **Decision Logging**: Document major architectural trade-offs in an Architecture Decision Record (ADR) format.

## 5. FORBIDDEN (LEADERSHIP SLOP)
*   **NO Nitpicking**: Focus on high-impact architectural issues first. Don't waste time on styling if the logic is broken.
*   **NO Rubber-stamping**: "LGTM" without a real review is an engineering sin.
*   **NO Knowledge Silos**: Every fix must be documented so the rest of the team learns from it.
*   **NO Inconsistent Directions**: Maintain a steady architectural vision. Don't flip-flop between patterns without a documented reason.
